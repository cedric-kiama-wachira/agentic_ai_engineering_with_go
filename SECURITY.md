# Security Policy

## Supported Versions

This repository is in active pre-release development. Security fixes are applied
to the default branch (`develop`) and the release branch (`main`). There are no
tagged releases under maintenance yet; this section will be updated when the
first release is cut.

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub issues,
pull requests, or discussions.**

Report privately through either channel:

1. **GitHub Private Vulnerability Reporting (preferred).** Go to the
   **Security** tab of this repository and choose **Report a vulnerability**.
   This routes the report privately to the maintainers.
2. **Email.** Send details to `theemail@mail.com`.
   > Interim bootstrap contact. This will be replaced by a monitored
   > organizational security mailbox when the repository migrates to the
   > enterprise (GHES) environment. See `docs/REPO_SETUP.md` for the migration
   > plan and recorded interim deviations.

### What to include

To help us triage quickly, please include where possible:

- A description of the vulnerability and its potential impact.
- Steps to reproduce, or a proof of concept.
- Affected component, file, branch, and commit if known.
- Any suggested remediation.

### Our commitment (coordinated disclosure)

- **Acknowledgement:** we aim to acknowledge a report within **3 business days**.
- **Assessment:** we aim to provide an initial assessment within
  **10 business days**.
- **Disclosure:** we follow coordinated disclosure. We will work with you on a
  remediation timeline and will credit reporters who wish to be acknowledged,
  once a fix is available. Please allow us reasonable time to remediate before
  any public disclosure.

We will keep you informed of progress throughout.

## Scope

This policy covers the code and configuration in this repository. It does not
cover third-party dependencies (report those to their respective maintainers),
though we welcome notice so we can update or mitigate.

## Safe Harbor

We will not pursue or support legal action against researchers who, in good
faith, discover and report vulnerabilities in accordance with this policy, and
who avoid privacy violations, service degradation, and data destruction during
testing.
